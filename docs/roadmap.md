# Implementation roadmap

Open implementation work, in recommended order. Architecture decisions live in `docs/architecture/open-questions.md`, this file tracks what remains to build and why. Prune entries as they land.

## Named limits of built work

The browser topology, leader election and the robustness pass are built, and these edges of them stay open.

- **A `Membership` dropped before it wins leadership leaves its lock request queued until context death**, because the browser only cancels a not-yet-granted request when the context dies. Real pages resign by dying, where this is a non-issue.
- **A write committed locally but never pushed is lost with the process.** The capture session is memory-only between the commit and the next flush, so a crash inside that window (typically one pump step) drops the upload while keeping the local row. Closing it means extracting changesets at commit time into the pending table, a different capture pipeline. The hub tier has the process-local sibling window between its replica apply and the worker's push persist.
- **A stale but non-empty snapshot cursor can still regress the resume point** (cursors are opaque to the client, so it cannot compare). Harmless with the in-memory sources (a regressed cursor only widens catchup or forces a resync), but snapshot sources SHOULD return the real watermark of their read.
- **The hub's upstream reconnect is exercised only indirectly** (its resume and re-subscribe path is the same machinery the native tests pin). A browser test would have to kill the shared demo server mid-run.

## Local-only tables

Core BUILT (client tier machinery, templates, tests) and hub fan-out BUILT (multi-tab notes sharing through the DB worker). Full contract in `docs/upstream-synql-tier-generation-contract.md`, decided entries in `docs/architecture/open-questions.md` section 10. Tier is document membership (two Postgres-dialect source files, bare table names, no schema prefix), placement is a second attached SQLite file, and writability is enforced physically.

- Two source documents, one per tier (`schema.sql` and `frontend.sql` in the demo, each baked to its own template by `build.rs`). Cross-document references are generation-time hard errors, live: pg2sqlite validates reference closure per document (default on since PR #46), so a `REFERENCES` crossing the boundary fails the bake, pinned by `cross_tier_reference_fails_the_template_bake`. The duplicate-name check belongs to synql, still pending.
- `ConnettoConnection::attach_local_tier(path)` attaches an existing frontend file (attach-create disabled around the attach, so a missing file fails loudly), `attach_local_tier_ddl(path, ddl)` creates it and applies the schema when the attached database is empty, with `":memory:"` giving the ephemeral tier a `:memory:` replica wants (tabs, tests). Since phase E2 that DDL flavor is also the only way to first-boot a durable tier under an encrypted replica, because the page codec gives an attached database main's key salt, as `docs/architecture/14-at-rest-encryption.md` records. The capture session stays on `main`, so local-only tables are physically incapable of uploading: a note write produces no `MutationHeader` (`push` returns `None`) and the destroy-on-reject hazard is gone by placement. Pinned by `crates/connetto-client/tests/local_tier.rs` and the browser test `examples/wasm-smoke/tests/local_tier.rs`.
- Live queries dispatch by a runtime lookup of the attached tier's catalog (`local_tables`): local rows skip the server subscription and refresh from local writes, local aggregates re-execute locally through the wire decoder (`json_quote` probe, bootstrap answered immediately), mixed rows auto-subscribe each synced table whole for the handle's lifetime (`SELECT * FROM "t"`, dropped with the handle), mixed aggregates hard-error at registration. All pinned by the tier test suites.
- Read-only synced tables are the other enforcement mechanism, kept distinct: pg2sqlite role translation, where the RLS branch already denies via a view without `INSTEAD OF` triggers and the non-RLS branch gains `RAISE(ABORT)` deny triggers (landed in the pinned pg2sqlite), with authoritative applies running in a triggers-disabled window. The server catalog stays as the version skew backstop.
- No cfg features in the generated crates: documents map to modules, the server consumes only the shared document, and the old deferred cell (visible-but-never-replicated tables for live aggregates) dissolves because local aggregates now have a home.
- Hub fan-out for local tables is BUILT (`examples/wasm-smoke/src/relay.rs`, pinned by `tests/notes_fanout.rs` in headless Chrome). The DB worker first-boots the frontend tier from DDL and the hub serves it through a `LocalTier`: a second connection whose main schema IS the tier file, because `sqlite3changeset_apply` only ever targets `main`. Tab mirrors hold both tiers in their main schema (`DEMO_TAB_DDL`) and the HUB keeps the tiers apart: a tab mutation is classified by the tables its changeset touches, a pure local one commits into the tier database together with a per-tab watermark (`_connetto_tab_mutations`, advanced in the same transaction, mirroring the server's per-writer frontier design), is acknowledged by the hub itself as the tier's terminal acknowledgement.

## Replica retention and eviction

The replica holds the union of subscribed query results, so bloat control decomposes into rotating time-windowed subscriptions (a standing `WHERE created_at > X` fixes `X` at registration, rotation means periodic re-subscribe with a fresh bound) and local eviction of rows no active subscription covers. Eviction MUST run with capture suspended (the same `SuspendedCapture` window server patches use): through live capture it would be recorded and sync to the backend as real deletes. Interplay with resume cursors and per table retention declared in the synql schema needs its own design doc before any code.

Physical file trimming belongs to the same design doc. Eviction alone leaves free pages, so the templates should bake `PRAGMA auto_vacuum = INCREMENTAL` (it must be set before the first table exists) and the client should run periodic `PRAGMA incremental_vacuum` plus `PRAGMA wal_checkpoint(TRUNCATE)` for WAL growth. For at-rest size, standard SQLite has no native page compression (ZIPVFS and CEROD are proprietary), and transparent column compression is ruled out after evaluation: `sqlite-zstd` is unusable here (it binds `rusqlite`, a second `libsqlite3-sys` pin against diesel's, and has no `wasm32-unknown-unknown` build at all), and a homegrown replacement would still be the same rename-view-triggers rewrite, which can never cover synced tables because `sqlite3changeset_apply` cannot deliver into a view (every row misfires as a per-row `Constraint` conflict that a server-wins policy omits, pinned by `crates/connetto-client/tests/rls_name_mapping.rs`) while changeset old-image comparisons would misfire against compressed bytes on every server UPDATE or DELETE. A frontend-only size win does not justify a runtime crate plus a pg2sqlite transform. If one frontend column ever genuinely bloats, the proportionate tool is explicit compression: the app calls `zstd` (already a workspace dependency, already exercised in the browser tests) and stores a BLOB. The frontend database bloats only with app-created data, so its tools are app deletion policy, vacuum, and explicit compressed columns, never sync-side eviction.

## wasm client, after the spike

De-risked so far: `sqlite-wasm-rs` compiles and links SQLite 3.53 with `SQLITE_ENABLE_SESSION` and `SQLITE_ENABLE_PREUPDATE_HOOK` for `wasm32-unknown-unknown` with the stock toolchain, and the spike's template-based first boot (`connect_with_plaintext_template`, now deleted by E5) mapped directly onto OPFS as fetch bytes, write file, no DDL execution. The spike, the relay increments, the robustness pass, and the multi-page election settle the topology, the transports, the driving mode, reconnect, and leadership.

The dioxus demo (`examples/dioxus-demo`) is VERIFIED end to end in a real browser (headless Chromium via `dx serve`, against `connetto-server` on 7777 and the long-lived `connetto-demo-pg`). Proven: a single window reaches `connected` and both panes render, "Add order" and "Save note" both write, two windows of one device converge on `orders` through the full Postgres CDC round trip and on `notes` through the DB worker hub without ever reaching the server, the tier boundary holds (new order ids land in Postgres `orders` while no `notes` table exists server side), and leader failover works (closing the leader lets a follower win the Web Locks election, spawn a replacement worker that resumes the OPFS replica from its persisted cursor, and keep serving, with a post-failover write round-tripping to Postgres).

Graceful degradation when OPFS is unavailable is also verified: `boot_db_worker` (`crates/connetto-web/src/workers.rs`) tries the sahpool OPFS VFS and, when the browser refuses it (a Firefox private window rejects `navigator.storage.getDirectory` with a `SecurityError`), falls back to the in-memory VFS that `sqlite-wasm-rs` already registers as the default at init. The worker still boots and serves the full topology for the session, trading away persistence and cross-window OPFS sharing. Proven in headless Chromium by forcing `getDirectory` to throw inside the real worker: sahpool calls it once, is rejected, and the worker still reaches `serving` with the tab `connected` and both `orders` (synced) and `notes` (device-local) writes applying.

The Yew adapter is DONE and verified. `connetto-yew` (`crates/connetto-yew`) is a root workspace member mirroring `connetto-dioxus`: one `use_live` hook dispatching at compile time through `Watchable`/`LiveHandle` so a row query yields state of `Vec<R>` and a scalar aggregate state of `Option<V>`. Yew's `spawn_local` is detached (unlike a dioxus scope task), so the hook wraps its driver in a `futures_util` `Abortable` and aborts it from the effect cleanup, preserving the drop-unsubscribe contract on unmount. The `examples/yew-web-demo` (built by trunk, served over the same `connetto-server` and `connetto-demo-pg`) is VERIFIED end to end in headless Chromium: a window reaches `connected`, "Add order" and "Save note" both write, two windows converge on `orders` through the full Postgres CDC round trip (client 380 matches Postgres 380) and on `notes` through the DB worker hub with no `notes` table server side. The remaining browser-track work is the smaller deferred items below.

The demos use `examples/icons/connetto.svg` for browser favicons and touch icons, Dioxus desktop window and bundle icons, and Tauri platform icons. Dioxus mobile app icons require upstream CLI support.

Worker bootstrap is owned by `connetto-web` and NEITHER demo ships a JS worker file. `spawn_db_worker` (`crates/connetto-web/src/workers.rs`) takes a `WorkerBootstrap` selecting how the app's glue initializes: `Glue` points the `Worker` straight at a self-initializing glue (dx appends an auto-init shim, so importing it instantiates the wasm and runs `main`). `Generated` builds a blob module that imports the glue and calls `init` with the wasm URL derived from the glue (for a stock wasm-bindgen glue such as trunk's, whose built-in default would fetch the un-hashed name). `Script(url)` keeps the older external-bootstrap path (a file that reads the glue from a `glue` query), still used by the `wasm-smoke` suite. In every mode the worker runs `main`, which boots the DB tier in its no-`Window` branch. The dioxus demo passes `Glue`, the Yew demo passes `Generated`, so both ship zero worker JS.

## Smaller deferred items

- `watch_fn(|| build_query())` closure variant for boxed and dynamic queries, which cannot carry the compile time dispatch markers. Done: `connetto-client` adds `ConnettoClient::watch_fn`, a row live query that sources each query instance from a `Fn() -> Q` factory instead of cloning a stored value, so a boxed (`.into_boxed()`) or otherwise dynamic query that is neither `Clone` nor marked can go live in `live.rs`. `watch` is now a thin delegation (`watch_fn(move || query.clone())`), leaving one row-watch implementation, and the factory is rendered once, run once for the offline-first initial load, then re-run per refresh, so it must build an equivalent query each call. The value path stays `watch_value_with` (a boxed aggregate renders once and never re-runs, so no factory buys anything). Proven in `tests/loop_emu.rs`: a boxed row query built by a closure goes live and refreshes on a CDC patch, it collapses onto one wire subscription with an equivalent typed `live()` watch, and an aggregate shape is rejected on the row path.
- `use_live_fn` adapter hooks wrapping `watch_fn` for boxed and dynamic row queries in components. Done: `connetto-dioxus` and `connetto-yew` each add `use_live_fn(client, build)` beside `use_live`, taking a query-builder closure and yielding the same `UseLive<Vec<R>>` for a boxed (`.into_boxed()`) or otherwise dynamic row query. Each mirrors its adapter's existing driver-cancellation contract (dioxus scope task drop, yew `Abortable` abort on unmount), so drop-unsubscribe still composes with the component lifecycle. The dioxus hook is proven by a `VirtualDom` test in `tests/hook.rs` (a boxed row query bootstraps from a seed row and follows a CDC insert), the yew hook compiles against the same bounds and rides the browser demo for its runtime proof, as the adapter has no headless vdom.
- Subscription dedup by SQL hash, so identical queries from many components share one server subscription. Done: `connetto-client` collapses identical `(query, binds)` specs onto one ref-counted wire subscription in `live.rs`, with aggregate fan-out and late-joiner bootstrap caching, proven in `tests/loop_emu.rs`.
- `LiveValue` decode support for custom user-declared aggregates beyond the built-in family. Done: `connetto-client`'s `AggregateWire` family now spans the standard diesel SQL types a custom aggregate returns (`Bool`, the temporal types, `Binary`, `Json` and `Jsonb`, and the non-nullable numeric and text variants), with `Uuid` and `Timestamptz` behind the opt-in `postgres-types` feature since the orphan rule bars a downstream crate from mapping diesel's own types. The wire-lenient primitives are public as `dsl::wire` so an application maps its own SQL type by implementing `AggregateWire` for it, and `watch_value_with` exposes the decoder-parameterized runtime path for boxed or dynamic value queries. The typed `live()` path classifies a custom aggregate from diesel's `IsAggregate` marker rather than the fixed function-name list, so the name-based SQL classification (the relay and untyped runtime paths) stays scoped to the built-in family on purpose. Pinned by `crates/connetto-server`'s `wire_contract` test (the exact `value_to_json` bytes), `connetto-client`'s decode unit tests, a temporal aggregate in `tests/loop_emu.rs`, and a custom-aggregate extension-seam case in `tests/local_tier.rs`.
- The demo id scheme (pid banded integers) stood in for a real distributed key strategy. Done: every app's synced `orders` table now authors client-generated UUID v7 blob keys through a column `DEFAULT (uuidv7())`, where pg2sqlite bakes `DEFAULT gen_random_uuid()` to `id BLOB PRIMARY KEY DEFAULT (uuidv7()) CHECK (length(id) = 16) NOT NULL` under `with_uuid_representation(Blob).with_uuid_function_name("uuidv7")`, and connetto mints the key on each connection it opens. connetto exposes a generic custom-SQL-function registrar, `SqlFunctions` on `ClientConfig` and `DbWorkerConfig` (`connetto-client/src/lib.rs`), applied right after `establish` at every connection seam, with no built-in functions: each app registers its own `uuidv7` (native `Uuid::now_v7`, wasm hand-built from `Date::now` plus `Math::random`), so an offline client authors a synced-table key with no server round trip and no coordination. Local-only tables (the demos' `notes`) stay integer by design, since a device-private single-writer table has no distributed-key requirement and integer keys keep the suite free of same-millisecond ordering concerns.
- The `SqlFunctions` registrar plus pg2sqlite's representation options (`with_uuid_representation`, `with_uuid_function_name`, and the wider representation surface) is the established pattern for supporting further non-obvious SQLite data types across all apps: declare the diesel function, bake the matching column `DEFAULT` or codec, and register the implementation on every replica connection connetto opens.
- Document and configure the SQLite hardening surface on replica connections (defensive mode, `set_attach_create_enabled`, `set_attach_write_enabled`, limits). The knobs exist in the pinned diesel fork and the upstream proposal is open as `diesel-rs/diesel#5128`. A vague security guarantee on its own, so it is a deliberate documentation and configuration pass, not enforcement.
